# Sphere protocol in Mockagent

Mockagent implements the HTTP/SSE boundary used when AgentSphere Executor calls an external agent. This page is a runnable reference for the subset described below. The [source models](../src/protocol/sphere/schema.py) define the exact fields accepted and emitted by this project.

## Request

Configure an external agent URL such as `http://mockagent:8000/v1/sphere/echo/chat`. Executor sends a bare JSON `AgentRequest` to this URL. The last URL segment selects the local agent. The older `{ "bot_id": "echo", "agent_request": { ... } }` wrapper is also accepted for compatibility with earlier mockagent clients.

```json
{
  "run_id": "run-1",
  "context_id": "conversation-1",
  "task_id": "task-1",
  "history": [
    {"role": "assistant", "parts": [{"type": "text", "text": "Earlier answer"}],
     "meta_data": {"generated_by_me": true}}
  ],
  "message": {
    "role": "user",
    "parts": [{"type": "text", "text": "Original question"}]
  },
  "augmented_context": {
    "rewritten_query": "Clarified question",
    "contains_pii": false
  },
  "configuration": {"execution_mode": "sub_agent", "enable_message": true},
  "meta_data": {"customer_option": "value"}
}
```

`message` is required. `role` is `user`, `assistant`, or `system`; `parts` may contain text, file, or structured data. A text part has `{"type":"text","text":"..."}`. A data part has `{"type":"data","data":{...}}`. A file part has `{"type":"file","file":{...}}`, where the file has a `kind` of `bytes`, `resource`, `url`, `text`, or `artifact`. `bytes` is Base64 encoded in JSON. Executor may replace resource and artifact files with URL files before forwarding; third-party agents should use the URL they receive rather than assume access to platform-only resource IDs.

`history` carries earlier messages when the caller manages conversation state; `context_id` lets an agent with its own state correlate turns. Message `meta_data.generated_by_me` can identify responses previously generated by the same agent. `augmented_context` may include `persona`, `topic_control`, `emotion_detection`, `long_term_memory`, `interrupt_resumes`, `contains_pii`, and `rewritten_query`. All are optional. An agent may use `rewritten_query` to understand the caller's clarified intent while retaining `message` as the original user input. `configuration.execution_mode` is `normal`, `sub_agent`, or `handoff`; it tells the agent how it is being called. Unknown extension fields are preserved in the parsed model.

The adapter makes the full parsed request available to an implementation as `Input.request`. The built-in Echo only reads text from the current `message` and the optional `rewritten_query`; it is useful for checking what Executor forwarded, but does not process files or history. Receipt logs contain IDs, the PII flag, and whether `rewritten_query` is missing, null, empty, or present. They do not log message or rewrite content.

## Response stream

Return HTTP `200` with `Content-Type: text/event-stream`. Each event is one JSON object on a `data:` line, followed by a blank line:

```text
data: {"type":"START","run_id":"run-1","task_id":"task-1"}

data: {"type":"STREAM_MESSAGE","content":"Answer text","run_id":"run-1","task_id":"task-1"}

data: {"type":"OUTPUT","parts":[{"type":"text","text":"Answer text"}],"run_id":"run-1","task_id":"task-1"}

data: {"type":"END","suggest_question":false,"run_id":"run-1","task_id":"task-1"}

```

Every event has a `type` and may carry `run_id`, `event_id`, `task_id`, and other metadata. Mockagent emits `START` and `END` around every run and fills missing `run_id` and `task_id` in agent-produced events. Other documented event bodies can be emitted through `WireEventOutput(event=...)`:

| Purpose | Event types | Key fields |
|---|---|---|
| Task and human input | `TASK`, `INPUT_REQUIRED_FORM`, `FOLLOW_UP_EXPECTED` | `task_status`, `interrupt_id`/`form` |
| Progress | `HEADER`, `STEP_THINKING`, `STEP_STREAM_REASONING_MESSAGE`, `STEP_TOOL`, `STEP_STREAM_MESSAGE` | `name`, `content`, `tool_name`/`tool_status` |
| Answer and handoff | `STREAM_MESSAGE`, `OUTPUT` | `content`, `parts` |
| Rich content | `CARD_REGISTER_REQUEST`, `STREAM_CARD`, `REFERENCE`, `AGENT_CUSTOM_MESSAGE` | `card_id`, `references`, `custom_message_type` |
| Policy and terminal outcome | `CONTAINS_PII`, `DISCLAIMER`, `INCAPABLE`, `ERROR` | `content`, `code`/`message`, `error_code`/`error_message` |

`STREAM_MESSAGE` is user-visible streamed text. `OUTPUT.parts` is the final handoff result for a caller or later agent; parts can be text or structured data. For human input, send `INPUT_REQUIRED_FORM` and a `TASK` event with `task_status="INPUT_REQUIRED"`; the next request carries answers in `augmented_context.interrupt_resumes`. `FOLLOW_UP_EXPECTED` asks the caller to route the next turn to the same agent. `INCAPABLE` signals an out-of-scope query; `ERROR` signals a failure. `STEP_TOOL.tool_status` values are lowercase `start` and `end`.

The built-in [demo agent](../src/framework/default/sphere_demo.py) emits a representative stream including a final `OUTPUT`. Run `uv run uvicorn server.app:app --reload`, then call `/v1/sphere/demo/chat` with the JSON request above. The [sample client](../examples/call_agent.py) sends a bare request and parses SSE events. Its `--agent-id demo` option selects the demo route.
